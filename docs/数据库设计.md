# 数据库设计（v1.0，对应已落地的 migrations）

## ER 关系

```
countries 1─N projects
teams 1─N specialties          （全公司共享，不挂项目）
projects 1─N subcategories ─── specialties 1─N subcategories
subcategories 1─N versions 1─N version_files
users N─N projects  (user_project，限制可见项目；管理员/超级管理员不受限)
users N─N teams     (user_team，限制可见团队；管理员/超级管理员不受限)
notifications 多态表，记录发给某个 user 的站内通知（新版本发布提醒）
audit_logs 记录 user_id + 对 team/specialty/subcategory/version/version_file 的操作
```

### users
| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| name | varchar | 姓名，用户可自助修改 |
| login_id | varchar unique | 工号 / 手机号，登录标识，不可自助修改 |
| password | varchar | bcrypt，用户可自助修改（需验证当前密码） |
| role | enum(construction,designer,admin,super_admin) | |
| is_active | bool | 禁用账号用，不物理删除 |

四级角色，管理员 / 超级管理员统称"管理层"（`User::isAdminTier()`），共享同一套内容与后台管理权限；区别只在账号管理：只有 `super_admin` 能创建 / 编辑 `admin` 或 `super_admin` 级别的账号（`User::canAssignRole()`），避免普通管理员随意提权。

### user_project（账号可见项目绑定）
| 字段 | 类型 | 说明 |
|---|---|---|
| user_id | FK → users | |
| project_id | FK → projects | |
| unique(user_id, project_id) | | |

管理层账号不查此表，视图 / 中间件层直接放行全部项目。

### user_team（账号可见团队绑定）
| 字段 | 类型 | 说明 |
|---|---|---|
| user_id | FK → users | |
| team_id | FK → teams | |
| unique(user_id, team_id) | | |

设计师 / 施工方账号只能看到被分配的团队（比如只负责机电、看不到土建 / 精装）；管理层不查此表，始终可见全部团队。细分类 / 版本 / 语言文件的查看与管理权限都同时校验 `hasProjectAccess()` 和 `hasTeamAccess()`。

### notifications（Laravel 标准站内通知表）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| type | varchar | 通知类的类名，如 `App\Notifications\NewVersionPublished` |
| notifiable_type / notifiable_id | 多态关联 | 指向 `users` |
| data | text(json) | 版本/细分类/团队/专业等展示信息 |
| read_at | timestamp nullable | 已读时间 |

新版本发布后，系统会给"同时拥有该项目和该团队权限"的设计师 / 施工方账号（不含上传者本人）各发一条；管理层已经能看到全部内容，不需要额外通知。

### version_files（按语言的"变更说明文件"，每语言最多一份，可选）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| version_id | FK → versions | |
| language | enum(zh,fr,en) | 所有语言均可选，可随时上传/替换/移除，不再强制 |
| doc_path / doc_size | varchar / bigint | 变更说明文件，doc/docx/xls/xlsx/pdf/txt/dwg 任一格式 |
| uploaded_by | FK → users nullable | |
| unique(version_id, language) | | 每版本每语言最多一条 |

DWG 原图和 PDF 图纸不在这张表里，见下面的 `version_drawings`。

### version_drawings（DWG 原图 / PDF 图纸，一次变更可以有多份，比如每层一张）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| version_id | FK → versions | |
| language | enum(zh,fr,en) | 中文至少要有 1 份 kind=dwg 的记录（唯一的强制项），法/英语和 PDF 全部可选 |
| kind | enum(dwg,pdf) | |
| file_path / file_size / original_name | varchar / bigint / varchar | COS 对象 key、字节数、原始文件名（用于下载时还原文件名、ZIP 打包时避免重名冲突） |
| dxf_path / dxf_status | varchar nullable | **DWG→DXF 交互式预览功能已停用**（图纸预览现在直接走 PDF），这两个字段代码里还留着但不再写入，恒为 null，见下方说明 |
| uploaded_by | FK → users nullable | created_at 即该份文件的"补充日期" |

删除单份 DWG/PDF 走 `App\Http\Controllers\VersionDrawingController::destroy`，会检查"中文至少留一份 DWG"这条规则，删光最后一份会被拒绝。按语言打包 ZIP 下载（`GET /versions/{version}/languages/{language}/zip`）把该语言下所有 DWG + PDF + 说明文件一起打包。

**删除变更（`versions`）时的 COS 清理**：`versions` 表本身是软删除（保留审计痕迹），但 `version_drawings`/`version_files` 没有软删除字段，删除一个变更时 `App\Http\Controllers\VersionController::destroy` 会先把该变更名下所有 DWG/PDF/说明文件（含转换出的 DXF，如果有）从 COS 物理删除，再把这些子表记录硬删除，最后才软删除 `versions` 本身——不然只删数据库记录，COS 存储空间不会释放。单独删除某一份 DWG/PDF/说明文件（`VersionDrawingController`/`VersionFileController` 的 `destroy`）同样是物理删除 + 硬删除记录，不是软删除。

**关于 DWG→DXF 预览的停用**：`App\Services\DwgConverter`、`App\Jobs\ConvertVersionDrawingDxf`、`dxf_path`/`dxf_status` 字段代码都还在仓库里，只是上传/追加 DWG 时不再触发转换任务了。图纸的在线预览改成直接读 PDF（`kind=pdf` 的记录），用 `<iframe>` 嵌入浏览器自带的 PDF 阅读器，翻页/缩放都是浏览器原生能力，不需要任何服务器端转换或前端库；没有 PDF 时显示"暂无图纸预览"，DWG 原图始终可以正常下载。

## 与原设计文档初稿的差异

1. 新增 `user_project` 表，落实"限制可见项目"的确认结论。
2. `teams` / `specialties` / `subcategories` / `versions` 增加 `deleted_at`（软删除），原初稿只在 `version_files` 做了唯一约束，未涉及软删除；现按"软删除 + 审计日志"结论补齐。
3. `users` 表去掉 `email` 唯一登录字段，改为 `login_id`（工号 / 手机号）+ `role` 枚举，不再需要 `password_reset_tokens` 表（一期不做自助找回密码，由管理员在后台重置）。
